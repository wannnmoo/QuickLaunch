# QuickLaunch 优化与新功能分析（基线 v1.15.1）

> 分析对象：`D:\QuickLaunch` 当前 HEAD（92866b3）
> 目的：先定位「哪里还能更好」，再决定做什么。不含代码改动。

## 一、体检结论

### 现状规模

| 文件 | 行数 | 说明 |
|---|---|---|
| `src/renderer/src/App.tsx` | 2990 | 单组件，47 个 `useState`，全部交互逻辑内联 |
| `src/main/index.ts` | 2913 | 窗口/z-order/命中区/IPC/PowerShell/图标 全在一个文件 |
| `src/renderer/src/App.css` | 1743 | 三主题靠选择器成组覆盖 |
| `src/preload/index.ts` | 249 | API 面 40+ 方法 |
| `devtools/**` | 224 文件 | 探针脚本，其中真正需要长期维护的约 8 个 |
| `CHANGELOG.md` | 136 KB | 单文件 |

功能面已经很完整：快捷方式/文件夹/系统位置、拖入即添加、拖拽排序、分组堆叠、分隔线、键盘导航、文件夹预览、盘符卡片、三主题、三档停靠、桌面图标开关、自启、托盘。

**所以「加功能」的瓶颈不在点子，而在三个结构性约束上。**

### 三个硬约束（决定了什么能做、什么只能绕）

1. **窗口 300px 高、`resizable: false`、透明窗口 resize 会白闪**（[index.ts:2880](src/main/index.ts#L2880)）。
   → 任何「大界面」（设置中心、网格启动器、多列面板）都**必须另开 BrowserWindow**，塞进 Dock 只能做「可滚动的下拉菜单」，而菜单已经到极限了（内容 ≈270px vs 可用 ≈200px，靠 `.dropdown-scroll` 硬撑）。
2. **`setShape` 命中区内缩上限 20px**（[index.ts:2197](src/main/index.ts#L2197)），玻璃条上方那条带天生「看得见、点不到」；浮层全靠 `overlayOpen` 放开整窗来绕。
   → 想再往下抠这块，只能走原生 `WM_NCHITTEST` 子类化，几何上没有余量了（标签顶边余量只剩 4.6px）。
3. **单 React 组件 + 全量重渲染**。任何一个 `setState`（比如文件夹图标分批推送、鼠标 hover）都要跑一遍 `App()` 函数体。
   → 新面板继续往 2990 行里加，回归风险是指数级的（现有代码里已经有 `sinkSeq`、`geoSeq`、`panelMeasuredKey`、`lastHitRegionRef` 等一堆手工竞态防护）。

## 二、优化清单

### A. 启动与运行时性能

- [ ] **A1 图标 base64 外置 + 自定义协议**（成本 0.5–1 天）
  现状：`AppEntry.iconDataUrl` 直接存在 `shortcuts.json` 里，每次 400ms 防抖都整份重写（[App.tsx:2323](src/renderer/src/App.tsx#L2323)）。60 个图标 ≈ 0.5–1 MB JSON，解析 + 序列化都在主线程。
  做法：图标落到 `userData/icons/<id>.png`，JSON 只存文件名；渲染侧用 `protocol.handle('ql-icon', ...)` 替代 data URL。
  收益：启动解析快、保存体积降到 KB 级、`.bak` 也小、内存里少了大量 base64 字符串。

- [ ] **A2 启动期不要跑列盘符**（0.2 天）
  [App.tsx:463](src/renderer/src/App.tsx#L463) 在挂载时就 `loadDrives()` 起一次 PowerShell，而卡片打开时还会再刷一次（[:488](src/renderer/src/App.tsx#L488)）。PowerShell 启动 + `Add-Type` 是 200ms 级开销。
  做法：首次悬停「此电脑」才取；启动时用 `requestIdleCallback` 预热。

- [ ] **A3 文件夹图标分批推送 → 局部渲染**（0.5 天，和 D1 一起做）
  每批 24 个图标就 `setState` 一次（[index.ts:1790](src/main/index.ts#L1790)），卡片开着时整个 App 重渲染 4+ 次。把 `FolderCard` 拆成 `memo` 子组件（或 `useSyncExternalStore` 小 store），图标更新只影响卡片。

- [ ] **A4 测量走 `offsetLeft/offsetWidth`**（0.2 天，收益小）
  `measureCenters` 每次全量 `getBoundingClientRect()`（[App.tsx:168](src/renderer/src/App.tsx#L168)）。同帧纯读不写其实不构成 layout thrashing，但 60 次 rect 仍可换成 offset 系列（不触发同步布局）。

- [ ] **A5 保存失败的可观测性**（0.2 天）
  现在失败只弹一次提示（`saveErrorHintedAt`）。加一次静默重试 + 写 `.bak` 后报「已降级保存」。

### B. 稳定性与可诊断性（**性价比最高的一块**）

- [ ] **B1 渲染进程崩溃看门狗**（0.3 天）
  主进程目前**没有** `render-process-gone` / `uncaughtException` 处理（全仓 grep 为空）。透明无边框窗口一旦 renderer 挂掉，用户看到的是「Dock 消失了，进程还在，Alt+Space 也没反应」——排查成本极高。
  做法：`render-process-gone` → 写日志 + 按当前 `dockEdge`/`dockTrayHidden` 重建窗口；`uncaughtException` → 落盘 + 单次对话框。

- [ ] **B2 落盘日志 + 诊断包导出**（0.5 天）
  现在只有 `console.error`（如 `setShape` 失败只打一次，见 [index.ts:2214](src/main/index.ts#L2214) 附近）。CLAUDE.md 里那些「实测三次才定位」的坑，一半靠日志能直接看出。
  做法：`userData/logs/main.log` 滚动（200 KB × 3）；打点「沉底/恢复/region 应用/PS 退出码/run-app 返回码/窗口重建」；「+」菜单加「导出诊断包」（日志 + 两份 JSON + 版本/显示器信息打包 zip）。

- [ ] **B3 dev 断言把不变量变成可执行代码**（0.3 天）
  `sinkSeq` 那套四层防护全靠注释维持。在 `canSinkNow` / `recoverDock` / `applyDockHitRegion` 入口加 `if (import.meta.env.DEV) assert(...)`，把「可见 + 未收托盘 + 代际一致 + region 覆盖玻璃条」写成断言。

- [ ] **B4 文档与代码漂移**（0.2 天）
  已知两处：CLAUDE.md 写 `FOLDER_CACHE_MAX` 上限 40，代码是 24（[index.ts:1788](src/main/index.ts#L1788)）；README 说托盘图标 16/20/24/32，实际六档。做法：常量集中在 `src/shared/constants.ts`，文档引用它，加个脚本核对。

- [ ] **B5 退出时保存竞态**（0.3 天）
  现在是 `before-quit` 推 flush + 留 200ms。可改成 `will-quit` 时 `preventDefault()` → 等写盘 Promise → 再 `app.quit()`（注意加一次性标志防死循环）。

- [ ] **B6 CSP**（0.2 天）
  [index.html](src/renderer/index.html) 无任何 CSP。加 `default-src 'self'; img-src 'self' data: ql-icon:; style-src 'self' 'unsafe-inline'`（图标协议化后顺手收口）。

## 四、新界面

### 1) 设置中心（独立窗口 760×560）— **最该做的一项**

现在的「+」菜单同时承担「动作」和「全部设置」：添加 / 桌面图标 / 自启 / 停靠位置（3 段）/ 主题（2 层 6 段）/ 版本号，已经要靠滚动。每加一个设置项都要挤进这 200px。

- 布局：左栏分类（通用 / 外观 / 行为 / 快捷方式 / 高级 / 关于），右侧表单，底部「重置本节」。
- 用**独立 BrowserWindow**（透明 Dock 不能长高）：`frame:false` + 自绘标题栏，复用现有 CSS 变量即可保持观感。
- 收益：解锁 C5/C6/E1/E2/E3/P0-1/P1-8 等所有配置项；Dock 菜单瘦身回 4 项动作。
- 配套：`settings.json` + 主进程广播 `settings-changed`；现有 `localStorage.ql-theme` / `ql-nav-last` 做一次性迁移。

### 2) 搜索浮层（Spotlight 式）

Dock 上方一条输入 + 最多 6 条结果（≈240px，正好在 300px 窗口内；浮层打开时 region 已放开整窗，点击没问题）。

- 触发：`Alt+Space` 唤出后**直接打字**即进入搜索（窗口已有焦点，不占用新热键，也不用改现有导航语义）。
- 结果分组：Dock 条目 / 桌面 `.lnk` / 最近文件；`↑↓` 选、`Enter` 启动、`Tab` 补全路径。
- 阶段一先只索引 Dock 内条目（当天出效果），阶段二加开始菜单索引。

### 3) 分组面板 → Launchpad 网格

现在面板是一行横排，10 个以上成员就要滚动。改成 4 列网格（最多 3 行可见），配合分组徽标，观感更像 macOS Launchpad。

### 4) 文件夹卡片双视图

列表（现状）/ 网格（图片类文件显示缩略图）；顶部加路径面包屑，点上级可回退。
顺带把 `list-folder` 的 5s TTL 提到 30s（反复进出同一目录现在会重复 `readdir`），加手动刷新按钮。

### 5) 右键菜单层级化

现在平铺 8 项（编辑/位置/管理员/复制/新建分组/分隔线/删除）。加二级「更多」收纳低频项，并为常用项加「固定到此分区」。

### 6) 拖到分组上的成员预览气泡

拖拽悬停在分组图标上时浮出该组现有成员缩略（3 个 + 计数），避免误放。

### 7) 首次启动引导

现在首启只有一个「+」。三步气泡：拖文件进来 → 拖到分组 = 收纳 → `Alt+Space` 键盘操作。

### 8) 托盘迷你面板

点托盘弹出 200×260 小面板（最近 6 个 + 「打开设置」），比只有两个菜单项好用。
