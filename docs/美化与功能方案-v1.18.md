## 〇、一句话结论

功能面已经相当完整。现在缺的是三层，而且三层都能用很小的改动换到明显观感：

1. **视觉减噪**：每个图标外面套了一块常驻"瓷砖"（衬底 + 内描边 + 顶部镜面 + 悬停辉光），
   60px 的槽位里画了 4 层装饰，图标只占 44px —— 密集时像一排按钮，不像 Dock。
2. **几何与尺寸脱钩**：`iconSize` 有 48/60/72 三档，但只有 `--dock-icon` 跟着变；
   分组拼图（46px 网格）、徽标（22px/7px）、面板内边距（64/56）、提示条（168/206）全是按 60 档写死的。
3. **状态反馈缺失**：点击 → 启动 → Dock 隐藏，中间没有任何视觉出口；运行中/失败都看不出来。

新功能里性价比最高的是**单图标全局热键**与**搜索启动** —— 两者的字段和入口其实都已经躺在代码里了（见 §一）。

## 二、美化清单

> 收益/成本按「用户一眼能看出来」和「动用多少既有几何」估。所有 V 项都不改窗口尺寸。

### V1 去掉常驻图标衬底（**收益最高，成本最低**）

**现状**（`App.css`）：`.dock-icon-wrap` 常驻 `--icon-wrap-bg`（三主题各一张渐变）+
`inset 0 0 0 1px rgba(255,255,255,.06)` 内描边 + `::before` 顶部镜面（悬停才淡入）+
悬停再加冷色辉光。图标本身是 `calc(--dock-icon - 16px)`，60 档 = 44px。

**改成**：默认**无衬底、无描边**，只在悬停/键盘选中时出现：

```css
.app {
  --icon-wrap-bg: transparent;
  --icon-wrap-hover-bg: rgba(255, 255, 255, 0.12);
  --icon-wrap-ring: transparent;
  --icon-wrap-ring-hover: rgba(255, 255, 255, 0.18);
}
.app.theme-light {
  --icon-wrap-hover-bg: rgba(0, 0, 0, 0.10);
  --icon-wrap-ring-hover: rgba(0, 0, 0, 0.14);
}
.dock-icon-wrap { box-shadow: inset 0 0 0 1px var(--icon-wrap-ring); }
.dock-item:hover .dock-icon-wrap { box-shadow: inset 0 0 0 1px var(--icon-wrap-ring-hover),
  0 6px 20px rgba(0,0,0,.35), 0 0 22px -6px rgba(96,165,238,.45); }
```

- 图标轮廓由已有的双层 `drop-shadow` 撑着，暗壁纸不会糊；`theme-transparent` 本来就是这套，观感已被验证。
- 顺带好处：图标之间不再有"框贴框"的视觉边界，V2 的间距微调才看得出来。
- 成本 0.2 天 · 风险低 · 验收：`node devtools/probe/hitregion-e2e.cjs`（region 由实测 rect 上报，与视觉无关，应全绿）。

### V2 间距 / 标签字号 / 悬停上浮随图标尺寸联动

**现状**：`gap: 4px`（60 档只有槽位的 6.7%，几乎贴上）；`.dock-label` 固定 `0.68rem`（≈10.9px）；
`useMagnify.ts` 的上浮固定 8px。三档尺寸下这三个值都不变 → 72 档显得"图大、间距小、字太小"。

**改成**（全部由已有的 `--dock-icon` 派生，不需要新增设置项）：

```css
.app {
  --dock-gap: calc(var(--dock-icon) * 0.11);              /* 60→6.6 48→5.3 72→7.9 */
  --dock-label-size: clamp(11px, calc(var(--dock-icon) * 0.2), 13px); /* 60→12 */
}
.dock-inner, .group-panel-inner { gap: var(--dock-gap); }
.dock-label { font-size: var(--dock-label-size); }
```

```ts
// hooks/useMagnify.ts:67 —— 上浮幅度也按尺寸缩放（60 档仍是 8px，保持现状）
const lift = dist < liftRange ? (1 - dist / liftRange) * (settingsRef.current.iconSize * 0.133) : 0
```

- ⚠️ `gap` 一变，`.dock-bar` 的 `max-content` 宽度与滚动阈值跟着变 —— region/命中都由实测 rect 上报，**不用改 JS**，但要重跑 `hitregion-e2e`（37 项）与 `regression.cjs` 第 7 组（滚动容器那组断言）。
- 顺手修一个隐性 bug：`applyZoom()` 的去重 key 只有 `scale`，`lift` 变了不会重写 transform；
  切 `top`/`middle`（`isTop` 翻转）时上浮方向反了但图标不动。改成 `${scale}|${lift}` 即可。
- 成本 0.2 天 · 风险低

### V5 「+」固定在玻璃条右端，不随滚动跑掉

**现状**：`+` 是 `.dock-inner` 的最后一个 flex 项 —— 图标一多就被滚到屏幕外，必须先滚到底才能添加。

**改成**：把 `.dock-add` 移出 `.dock-inner`，作为 `.dock-bar` 的兄弟节点常驻右侧，
前面加一条 1px 分隔线（`--sep-color`），`.dock-inner` 的可用宽度减去 `+` 的槽位：

```

.dock-bar  { display: flex; align-items: flex-end; }
.dock-inner{ max-width: calc(100% - var(--dock-icon) - 16px); }
```

- 键盘导航不用改：`ADD_BTN_ID` 仍是哨兵，`→` 到最右仍落到它。
- ⚠️ region 仍按 `.dock-bar` 实测 rect 报，`+` 在 bar 内，不影响命中；
  但 `.dock-edge.right` 的定位基准是 bar，视觉上要改成落在 `.dock-inner` 右缘（否则渐隐遮罩压住 `+`）。
- 成本 0.5 天 · 风险中（动布局结构）· 验收：`regression.cjs` 第 7 组 + 手动加 30 个图标确认 `+` 可见可点。

### V6 启动反馈：弹跳 + 失败抖动（**手感就是这个应用的脸**）

**现状**：点击 → `run-app`（4~10ms）→ `hideDockAfterLaunch()` 同步隐藏。中间 0 帧反馈；
失败只在 ~400ms 后弹一条 `drop-hint`。

**改成**：

```css
@keyframes launch-bounce {
  0%   { transform: translateY(0) scale(1); }
  35%  { transform: translateY(-9px) scale(1.10); }
  70%  { transform: translateY(0) scale(.985); }
  100% { transform: translateY(0) scale(1); }
}
@keyframes launch-shake {
  0%,100% { transform: translateX(0); }
  20% { transform: translateX(-3px); } 40% { transform: translateX(3px); }
  60% { transform: translateX(-2px); } 80% { transform: translateX(2px); }
}
/* ⚠️ 动画挂在 .dock-icon（<img>）上，不要挂 .dock-icon-wrap：
   后者的 transform 已被放大/选中/归组的内联样式占用，动画会与之互相覆盖 */
.dock-item.launching .dock-icon { animation: launch-bounce .42s cubic-bezier(.34,1.56,.64,1); }
.dock-item.launch-failed .dock-icon { animation: launch-shake .26s ease-in-out; }
@media (prefers-reduced-motion: reduce) { .dock-item.launching .dock-icon,
  .dock-item.launch-failed .dock-icon { animation: none; } }
```

renderer：`handleRun` 里先 `setLaunchingId(id)`，`run-app` 回来后 `false` → `setLaunchFailedId(id)` 600ms 后清。
主进程：`hideDockAfterLaunch()` 加 `delay = 260`（**只在 `afterLaunch === 'hide'` 时延迟**）：

```ts
// 伪代码：立即 sinkSeq++（作废在途沉底），hide 放进定时器，末尾比对代际
const seq = ++sinkSeq
hideTimer = setTimeout(() => {
  hideTimer = null
  if (sinkSeq !== seq || !win || win.isDestroyed()) return
  dockTrayHidden = true
  win.hide()
}, 260)
```

- 🚫 **所有"唤回"路径（`toggleWindow` 显示分支 / 托盘 / `second-instance` / `recoverDock`）必须先 `clearTimeout(hideTimer)`**，
  否则迟到的 hide 会把刚唤回的 Dock 又藏起来 —— 这就是 `sinkSeq` 那套四层防护的同款陷阱。
- 成本 0.4 天 · 风险中 · 验收：`visibility-state.cjs`（5 场景）+ `runapp-fixed.cjs`（返回值时序）+ 手动测"点击后在 100ms 内按 Alt+Space"。

## 附录 B：本次读代码顺手发现的两处小问题

1. `dockGeometry.applyZoom()` 用 `WeakMap<HTMLElement, number>` 只记 `scale`，
   `lift` 变化不重写 —— 切 `top`/`middle` 时上浮方向反了但 transform 不变。key 改成 `${scale}|${lift}`。
2. `.dock-item { gap: 5px }` 是死样式：`.dock-label` 是绝对定位，`.dock-icon-wrap` 是唯一在流内子项，gap 永远不生效。
   删掉或改成给未来"图标下方常驻标签"预留的 `--dock-item-gap`。
